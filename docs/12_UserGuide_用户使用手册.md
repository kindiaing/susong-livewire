# 本地速送管理后台 — 用户使用手册

版本：V1.12.0
更新日期：2026-08-20
适用系统：本地速送管理后台（Laravel Livewire 桌面端）

---

## 1 系统概述

本地速送是一个本地生鲜配送服务平台，管理后台用于运营人员、财务专员、拣货员、配送司机等角色进行日常业务操作。

**访问地址**：https://livewire.test（开发环境）

**浏览器要求**：Chrome 90+ / Edge 90+ / Firefox 90+（仅桌面端，不支持移动端）

---

## 2 登录与退出

### 2.1 登录

1. 打开浏览器，访问系统地址
2. 在首页点击「登录」按钮，进入登录页
3. 输入用户名/手机号/邮箱和密码
4. 可勾选「记住登录状态」（7 天内免登录）
5. 点击「登录」按钮

> 连续 5 次登录失败后账户将被锁定 1 分钟。

**超级管理员初始账号**：

| 项目 | 值 |
| :--- | :--- |
| 用户名 | seeding |
| 密码 | Password |

### 2.2 退出

点击右上角用户名 → 选择「退出登录」，系统将返回首页。

## 3 导航布局

系统采用顶部水平导航栏布局：

```
┌──────────────────────────────────────────────────────────────┐
│  [Logo] 本地速送  │  [导航菜单...]  [Ctrl+K搜索]  │  🔔 ⚙️ │ 用户 ▼│
└──────────────────────────────────────────────────────────────┘
│                        内容区域                                │
```

- **左侧**：系统 Logo + 名称
- **中间**：导航菜单 + 命令搜索框
- **右侧**：通知铃铛、界面设置、用户菜单

### 3.1 快捷搜索（Ctrl+K）

按 `Ctrl+K` 打开命令面板，可快速搜索并跳转到任意功能页面。输入关键词后，系统实时过滤匹配的菜单项，按回车直接跳转。

## 4 功能模块说明

### 4.1 用户权限

#### 4.1.1 用户管理

**路径**：导航栏 → 用户权限 → 用户管理
**路由**：`/users`

| 操作 | 说明 |
| :--- | :--- |
| 查看列表 | 显示所有用户，含用户名、姓名、联系方式、状态开关、角色标签，支持按用户名/姓名/手机/邮箱搜索 |
| 新增用户 | 点击「新增用户」，填写用户名、姓名、手机、邮箱、密码、状态 |
| 编辑用户 | 点击行内铅笔图标修改基本信息（密码留空不修改） |
| 分配角色 | 点击行内盾牌图标，在弹窗中勾选角色（支持多选） |
| 禁用/启用 | 点击行内状态列的 toggle 开关直接切换（不能禁用当前登录用户和超级管理员） |
| 重置密码 | 点击行内钥匙图标，确认后将密码重置为 `Password` |
| 删除用户 | 点击行内垃圾桶图标，确认后删除（不能删除当前登录用户和超级管理员） |

状态开关：启用（绿色滑块右侧）/ 禁用（灰色滑块左侧）。超级管理员行不显示 toggle 开关和删除按钮。
操作图标：铅笔（编辑）/ 盾牌（角色分配）/ 钥匙（重置密码）/ 垃圾桶（删除），hover 时有背景高亮。

#### 4.1.2 角色管理

**路径**：导航栏 → 用户权限 → 角色管理
**路由**：`/roles`

| 操作 | 说明 |
| :--- | :--- |
| 查看列表 | 显示所有角色，含用户数、权限数，支持按名称搜索 |
| 新增角色 | 点击「新增角色」按钮，在弹窗中填写角色标识、显示名称、描述 |
| 编辑角色 | 点击行内铅笔图标，在弹窗中修改信息（super-admin 角色不可编辑） |
| 分配权限 | 点击行内盾牌图标，在弹窗中勾选权限（模块→页面→按钮 树形结构） |
| 删除角色 | 点击行内垃圾桶图标，确认后删除（有用户的角色不可删除，super-admin 角色不可删除） |

系统预置 9 个角色：超级管理员、运营专员、财务专员、拣货员、配送司机、商家、出纳、财务经理、运营经理。

权限树结构：模块级 → 页面级 → 按钮级，三级 checkbox 支持三态联动（选中/半选/未选）。勾选模块自动全选子页面+按钮，勾选页面自动全选子按钮。半选状态（indeterminate）由 Alpine `x-effect` 驱动显示。

#### 4.1.3 权限管理

**路径**：导航栏 → 用户权限 → 权限管理
**路由**：`/permissions`

| 操作 | 说明 |
| :--- | :--- |
| 查看列表 | 显示所有权限，含类型标签（模块/页面/按钮）、关联角色数，支持搜索 |
| 新增权限 | 点击「新增权限」按钮，选择类型、上级权限、填写标识和显示名称 |
| 编辑权限 | 点击行内铅笔图标修改 |
| 分配角色 | 点击行内盾牌图标，在弹窗中勾选关联角色（支持多选） |
| 删除权限 | 点击行内垃圾桶图标确认删除（被角色引用的权限不可删除） |
| 类型筛选 | 下拉选择「全部类型/模块/页面/按钮」实时筛选 |
| 模块筛选 | 下拉选择「全部模块/指定模块」筛选该模块及其子级（页面+按钮） |
| 组合筛选 | 类型+模块可组合使用，点击「重置」清空所有筛选条件 |

权限分为三级：模块级 → 页面级 → 按钮级。

SKU 价格字段说明：

| 字段 | 说明 |
| :--- | :--- |
| purchase_price | 标准采购价（厘） |
| cost_price | 加权平均成本价（厘） |
| min_purchase_price | 最低采购限价（厘） |
| list_price | 吊牌价/标价（厘） |
| retail_price | 标准零售价（厘），作为渠道价回退基准 |
| wholesale_price | 批发团购价（厘） |
| employee_price | 员工内部价（厘） |
| offline_price | 门店渠道基准价（厘），为 0 时回退到 retail_price |
| miniapp_price | 小程序渠道基准价（厘），为 0 时回退到 retail_price |
| delivery_price | 外送渠道基准价（厘），为 0 时回退到 retail_price |
| min_sale_price | 最低销售限价（厘） |
| max_sale_price | 最高销售限价（厘） |

> 金额字段均以"厘"为单位存储（整数），页面显示自动转换为"元"（÷1000，保留 2 位小数）。

SKU 编辑弹窗包含两个 Tab 页签：

| Tab | 说明 |
| :--- | :--- |
| 基本信息 | 填写 SKU 规格和价格信息 |
| 单位换算 | 配置该 SKU 的多级单位换算链路（详见第 9 章） |

> 单位换算为可选配置。未配置换算关系的 SKU，库存和数量按默认单位管理。

## 7 取价逻辑

系统在结算、下单、开票等场景中，需要根据一系列规则确定商品的最终售价。取价逻辑支持**两种模式**，可通过「系统管理 → 取价配置」页面切换。

### 7.1 取价来源

系统共有 5 个取价来源，每个来源可独立开关：

| 来源 | 标识 | 说明 |
| :--- | :--- | :--- |
| 促销活动 | `promotion` | 秒杀/拼团/清仓/套餐/普通促销的固定价或折扣率 |
| 门店差异化 | `store` | 特定门店独立定价或上浮下调 |
| 会员折扣 | `member` | 会员等级折扣率（万分比），常驻或限时 |
| 渠道基准价 | `channel` | offline / miniapp / delivery 三渠道，为 0 回退 retail_price |
| 标准零售价 | `retail` | retail_price，兜底必选不可关闭 |

> 优惠券和满减属于**订单级**优惠，在取价完成后于订单总价层面计算减免，不直接改变商品单价。

### 7.2 取价模式

#### 模式一：最低价模式（推荐）

**路径**：系统管理 → 取价配置 → 最低价模式

**逻辑**：所有启用的固定价来源取**最低值**，再叠乘会员折扣率。

```
第1步：收集所有启用的固定价来源，取最低
       ├─ 促销活动价
       ├─ 门店差异化价
       ├─ 渠道基准价（回退到 retail_price）
       └─ 标准零售价
       → basePrice = min(所有非零固定价)

第2步：叠乘会员折扣率
       → basePrice × (discount_rate / 10000)

第3步：限价校验（硬约束）
       → clampToLimits(price, min_sale_price, max_sale_price)
```

**示例**：促销价 80 元 + 零售价 100 元 + 会员 9 折 → min(80, 100) × 0.9 = **72 元**

#### 模式二：命中即止模式

**路径**：系统管理 → 取价配置 → 命中即止模式

**逻辑**：按优先级从高到低遍历，第一个有值的来源即最终价（会员折扣作为独立来源参与排序）。

```
第1步：按优先级遍历取价来源
       → 遍历 pricing_priority 配置的顺序
       → 第一个返回有效价格的来源即最终价

第2步：限价校验（硬约束）
       → clampToLimits(price, min_sale_price, max_sale_price)
```

**示例**（优先级：促销 > 会员 > 渠道 > 零售）：促销价 80 元命中 → **80 元**（会员折扣被跳过）

### 7.3 两种模式下会员折扣的差异

| 场景 | 最低价模式 | 命中即止模式 |
| :--- | :--- | :--- |
| 促销 80 + 零售 100 + 会员 9 折 | 80 × 0.9 = **72** | 促销优先命中 = **80** |
| 无促销 + 零售 100 + 会员 9 折 | 100 × 0.9 = **90** | 会员优先于零售 = **90** |
| 促销 80 + 零售 100 + 会员关 | **80** | **80** |

**核心差异**：最低价模式下会员折扣不会白配；命中即止模式下促销和会员互斥。

### 7.4 取价配置组合清单

#### 最低价模式（L1-L9）

| 编号 | 启用来源 | 取价公式 | 典型场景 |
| :--- | :--- | :--- | :--- |
| L1 | retail | retail_price | 最简单定价，无任何优惠 |
| L2 | channel + retail | min(channel, retail) | 多渠道不同价，取最低 |
| L3 | channel + member + retail | min(channel, retail) × 会员折扣 | 常规零售：渠道价 + 会员折扣叠乘 |
| L4 | promotion + channel + retail | min(促销价, channel, retail) | 促销期间，自动取最低 |
| L5 | promotion + channel + member + retail | min(促销价, channel, retail) × 会员折扣 | **最常用**：促销 + 会员双重优惠 |
| L6 | store + channel + member + retail | min(门店价, channel, retail) × 会员折扣 | 门店差异化 + 会员，无促销 |
| L7 | promotion + store + channel + member + retail | min(促销价, 门店价, channel, retail) × 会员折扣 | 全来源开放，消费者最友好 |
| L8 | promotion + channel + retail（关 member/store） | min(促销价, channel, retail) | 促销期间关闭会员折扣，防双重优惠 |
| L9 | store + channel + retail（关 promotion/member） | min(门店价, channel, retail) | 纯门店+渠道定价 |

#### 命中即止模式（F1-F7）

| 编号 | 启用来源 + 优先级顺序 | 取价结果 | 典型场景 |
| :--- | :--- | :--- | :--- |
| F1 | retail | retail_price | 同 L1 |
| F2 | promotion > channel > retail | 促销优先，否则渠道价，否则零售价 | **常规控价**：促销严格覆盖 |
| F3 | promotion > store > channel > retail | 促销优先，否则门店价 | 促销覆盖门店差异化 |
| F4 | store > promotion > channel > retail | 门店价优先，促销兜底 | **门店加盟**：门店自主定价权最大 |
| F5 | promotion > member > channel > retail | 促销优先，否则会员折扣价 | 会员折扣排第二 |
| F6 | channel > retail（关 promotion/store/member） | 渠道价，无则零售价 | 纯渠道差异化定价 |
| F7 | member > channel > retail（关 promotion/store） | 会员折扣价 > 渠道价 > 零售价 | 会员尊享价优先 |

#### 推荐默认配置

| 场景 | 推荐配置 | 理由 |
| :--- | :--- | :--- |
| 初期上线 | L5（最低价 + 促销/渠道/会员） | 消费者体验最好，运营理解成本最低 |
| 成本敏感期 | F2（命中即止 + 促销优先） | 严格控价，防止双重优惠 |
| 门店加盟模式 | F4（门店价优先） | 门店自主定价权最大 |
| 促销大促期 | L8（最低价 + 关会员） | 促销已足够优惠，关闭会员防漏 |

### 7.5 限价校验（硬约束）

无论哪种模式，最终售价必须通过限价校验：

- `min_sale_price > 0` 且售价 < 最低限价 → 强制取最低限价
- `max_sale_price > 0` 且售价 > 最高限价 → 强制取最高限价
- 两者均为 0 时不限制

### 7.6 改价日志

所有非零售价的改价行为均写入 `price_change_logs`，`source_type` 标识 11 种来源：1促销、2临时改价、3手动改价、4满减、5优惠券、6组合套餐、7清仓、8拼团、9秒杀、10会员折扣、11门店差异化。

## 8 金额精度与舍入

系统所有金额以"厘"（1厘 = ¥0.001）为最小单位存储，采用**三层分离**架构确保计算精度：

### 8.1 三层分离

| 层面 | 说明 |
| :--- | :--- |
| 存储层 | 所有金额以整数厘存入数据库（BIGINT），固定不变 |
| 计算层 | 后端所有运算在厘级完成，零精度丢失 |
| 显示层 | 通过 `money_format()` 将厘转为元显示，精度和舍入方式可配置 |

### 8.2 配置入口

**路径**：导航栏 → 系统管理 → 系统配置 → 金额精度

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 金额显示精度 | 2位（分） | 全局金额显示保留几位小数，可选2位/3位 |
| 称重数量精度 | 3位（厘） | 称重数量输入框接受几位小数，可选2位/3位 |
| 全局默认舍入 | 四舍五入 | 未单独设置的模块将使用此方式 |
| 订单模块舍入 | 四舍五入 | 消费者标准 |
| 采购模块舍入 | 截断抹零 | 采购方不利零头 |
| 充值模块舍入 | 向上取整 | 保护平台 |
| 结算模块舍入 | 四舍五入 | 财务标准 |
| 取价/促销舍入 | 四舍五入 | 价格展示标准 |
| 库存损耗舍入 | 截断抹零 | 避免虚增损耗 |
| 发票模块舍入 | 四舍五入 | 税务合规 |

> 修改即时生效，无需重启服务。

### 8.3 四种舍入模式

| 模式 | 说明 | 示例 |
| :--- | :--- | :--- |
| 四舍五入 | 标准舍入 | ¥3.145 → ¥3.15 |
| 向上取整 | 金额偏大方向取整 | ¥3.141 → ¥3.15 |
| 向下取整 | 金额偏小方向取整 | ¥3.149 → ¥3.14 |
| 截断抹零 | 直接截断多余位 | ¥3.149 → ¥3.14 |

### 8.4 称重场景精度

称重数量精度与金额显示精度是**两个独立设置**：

| 场景 | 数量精度 | 金额精度 | 典型业务 |
| :--- | :--- | :--- | :--- |
| 精密秤（1克级） | 3位 | 3位 | 高价值水产、肉品 |
| 普通秤（50克级） | 2位 | 2位 | 蔬菜、粮油 |
| 整件计价 | 0位 | 2位 | 标品、桶装油 |

### 8.5 关于尾差

在 2 位精度下，明细金额各自舍入后，其显示之和可能与汇总金额有几分钱的差异，这是数学舍入的正常现象（尾差）。

**系统处理策略**：

- 汇总金额 = 后端厘级求和后直接转换，**数据绝对精确**
- 明细金额 = 各自独立舍入显示
- 前端**不对明细金额求和**作为汇总，汇总值从后端直接取
- 列表页底部提示：`* 金额以厘级计算为准，显示可能存在舍入尾差`

**示例**：

```
大白菜：9200厘/斤 × 2100厘斤 / 1000 = 19320厘 → 2位显示 ¥19.32
土豆：  13800厘/斤 × 480厘斤 / 1000 = 6624厘 → 2位显示 ¥6.62
汇总：  19320 + 6624 = 25944厘 → 2位显示 ¥25.94
前端求和：¥19.32 + ¥6.62 = ¥25.94 ✅ （此例恰好一致，换组数据可能差±0.01）
```

如需消除视觉尾差，可将"金额显示精度"设为 3 位（厘级显示）。

## 9 单位换算

系统支持按 SKU 配置多级单位换算关系（如 1箱=6件，1件=10包），实现采购按箱、发货按件/包的灵活计量需求。库存统一以最小单位（base_unit）存储，列表页自动换算显示。

### 9.1 设计原理

单位换算采用**最小单位存储**策略，与金额以"厘"为最小单位的设计思路一致：

| 层面 | 说明 |
| :--- | :--- |
| 存储层 | 库存、订单数量统一以 SKU 的最小单位（base_unit）存入数据库 |
| 换算层 | 通过 UnitConversionService 实现任意单位之间的换算 |
| 显示层 | 列表页自动将最小单位数量转换为 human 格式（如 130包 → "2箱1件10包"） |

> **为什么用最小单位存储？** 与金额用"厘"存储同理：避免多单位换算时的精度丢失，确保库存数据精确，所有运算在最小单位层级完成。

### 9.2 设置顺序

单位换算功能需要按以下顺序配置：

```
第1步：系统管理 → 单位管理（/units）
       ├─ 确认预置单位是否满足需求
       ├─ 按需新增自定义单位
       └─ 启用/禁用单位

第2步：商品管理 → SKU 管理 → 编辑 SKU → 单位换算 Tab
       ├─ 选择最小计量单位（base_unit）
       ├─ 添加换算链路行（从大到小排列）
       ├─ 填写换算系数（如 1箱=6件，系数填6）
       └─ 保存

第3步：下单/采购时自动生效
       ├─ 输入数量时可选单位（箱/件/包...）
       └─ 系统自动换算为 base_unit 存储
```

### 9.3 换算链路规则

换算关系是 **SKU 级别**的（不同商品的箱装数可能不同），且采用**严格单链路**设计：

| 规则 | 说明 |
| :--- | :--- |
| SKU 级别 | 每个 SKU 独立配置换算关系（A商品 1箱=6件，B商品 1箱=12件） |
| 严格单链路 | 同一 SKU 只能有一条换算链路（箱→件→包），不可分叉 |
| 无限级扩展 | 支持任意级数（实际业务一般3级：箱→件→包） |
| 链路串联 | 换算关系通过 parent_conversion_id 串联，形成链路 |

**换算链路示例**（SKU 基本单位=包）：

```
箱 ──(1箱=6件)──→ 件 ──(1件=10包)──→ 包（base_unit）

1箱 = 6件 = 60包
2箱1件10包 = 2×60 + 1×10 + 10 = 130包
```

### 9.4 SKU 换算配置操作

1. 进入 **商品管理 → SKU 管理**，点击某个 SKU 的「编辑」按钮
2. 在弹窗中切换到「单位换算」Tab
3. 在「最小计量单位」下拉框中选择 base_unit（如"包"）
4. 点击「添加换算行」，依次配置从大到小的换算关系：
   - 第1行：从=箱，到=件，系数=6（即 1箱=6件）
   - 第2行：从=件，到=包，系数=10（即 1件=10包）
5. 链路预览区域实时显示完整链路（如"箱 → 件 → 包"）
6. 点击「保存」

> 系统会自动校验链路完整性：每行的「到单位」必须与下一行的「从单位」一致，且最终到达 base_unit。不完整的链路无法保存。

### 9.5 换算示例

| 场景 | 输入 | 换算结果 | 说明 |
| :--- | :--- | :--- | :--- |
| 库存展示 | 130（包） | 2箱1件10包 | human 格式化显示 |
| 下单选箱 | 2箱 | 120包 | 转为 base_unit 存储 |
| 下单选件 | 5件 | 50包 | 转为 base_unit 存储 |
| 下单回显 | 120包 | 2箱（120包） | 显示大单位+括号备注 |

### 9.6 适用场景

| 场景 | 典型单位链路 | 说明 |
| :--- | :--- | :--- |
| 标品箱装 | 箱→件→包 | 1箱=6件，1件=10包 |
| 散装称重 | 斤→两 | 1斤=10两（或仅用斤） |
| 桶装 | 桶→瓶 | 1桶=24瓶 |
| 无换算 | 个/条 | 无需配置，直接使用 |

### 9.7 全链路单位换算流程

单位换算贯穿从下单到配送的完整业务链路，每个环节自动处理换算，用户无需手动转换：

```
                         单位换算贯穿全链路
 ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
 │  购物车   │    │ 客户订单  │    │ 待采清单  │    │  采购单   │    │  拣货任务 │
 │ (Cart)   │    │ (Order)  │    │ (Purchase │    │(Purchase │    │ (Picking)│
 │          │───→│          │───→│   Item)  │───→│  Order)  │───→│          │
 │ 选单位   │    │ 存base   │    │ 选单位   │    │ 存base   │    │ 存base   │
 │ 输数量   │    │ 显示换算 │    │ 输数量   │    │ 显示换算 │    │ 显示换算 │
 └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                                        │
                                                                        ▼
                                                               ┌──────────────┐
                                                               │  送货单       │
                                                               │(DeliveryNote)│
                                                               │ 显示换算     │
                                                               └──────────────┘
```

各环节单位换算处理方式：

| 业务环节 | 输入方式 | 存储方式 | 显示方式 |
| :--- | :--- | :--- | :--- |
| 购物车 | 选单位 + 输入数量（如 2箱） | base_unit 数量（如 120包） | "2箱（120包）"格式 |
| 客户订单 | 购物车生成时自动带入 | base_unit 数量 | 列表显示 base_unit 数量 |
| 待采清单 | 选单位 + 输入数量（如 5件） | base_unit 数量（如 50包） | "5件（50包）"格式 |
| 采购单 | 待采清单生成时自动带入 | base_unit 数量 | 列表显示 base_unit 数量 |
| 拣货任务 | 系统自动汇总 | base_unit 数量 | "2箱1件10包"human 格式 |
| 送货单 | 系统自动拆分生成 | base_unit 数量 | "2箱1件10包"human 格式 |

> **核心原则**：所有业务数据统一以 base_unit（最小单位）存储，输入时可选大单位（系统自动换算），显示时根据场景选择合适的格式。

### 9.8 各业务环节操作说明

#### 购物车中的单位换算

在购物车添加商品时：

1. 选择 SKU 后，系统自动选中该 SKU 的 base_unit 作为默认单位
2. 点击单位下拉框可切换为其他单位（如从"包"切换到"箱"）
3. 输入单位数量（如输入 2，表示 2 箱）
4. 系统实时换算并显示预览："2箱（120包）"
5. 保存时系统自动将数量转换为 base_unit 存储（如 120 包）
6. 编辑已有项时，自动回显原选单位 + 原输入数量

> 同一购物车中相同 SKU 的商品会自动合并，单位数量累加。生成订单时，unit_id 和 unit_quantity 一并传递到订单明细。

#### 待采清单中的单位换算

在待采清单添加商品时，单位换算逻辑与购物车一致：

1. 选择 SKU → 自动选中 base_unit
2. 可切换单位并输入数量
3. 系统实时换算显示预览
4. 保存为 base_unit 存储
5. 生成采购单时，unit_id 和 unit_quantity 自动带入采购明细

#### 拣货任务中的单位换算

拣货任务由系统从订单自动生成，无需手动输入单位：

- **汇总显示**：拣货明细按 SKU 汇总，数量以 human 格式显示（如"2箱1件10包"）
- **拣货出库**：拣货完成时，系统按 picked_quantity（base_unit 数量）逐 SKU 执行出库
- **拣货列表**：列表页显示 base_unit 数量的纯数字格式

#### 送货单中的单位换算

送货单按商家维度从配送任务拆分生成：

- **明细显示**：数量和已拣数量均以 human 格式显示（如"2箱1件10包"）
- **单位标注**：明细行显示该 SKU 的 base_unit 名称
- **无需手动操作**：送货单数据全部由系统自动生成

## 11 常见问题

### Q: 为什么明细金额之和与汇总金额差几分钱？
A: 这是正常的舍入尾差。系统在厘级（0.001元）运算，显示时按配置精度（默认2位）舍入。汇总金额是后端厘级求和后转换，数据绝对精确。前端不对明细求和，如需消除视觉尾差，可将显示精度设为3位。

### Q: 登录时提示"页面已过期"？
A: Session 已过期，页面会自动刷新，刷新后重新登录即可。

### Q: 修改配置后没有生效？
A: 系统配置修改后即时生效。如未生效，请尝试刷新浏览器（Ctrl+F5）。

### Q: 忘记密码怎么办？
A: 联系超级管理员重置密码。

### Q: 审核节点开关关闭后，还需要审核吗？
A: 关闭审核节点后，对应业务操作将跳过审核流程，直接执行。

### Q: 操作日志为什么有些操作没有记录？
A: 系统仅记录写操作（增/删/改），查询操作不计入。同时会过滤 Livewire 内部请求。

### Q: 不配置单位换算会怎样？
A: 不影响正常使用。未配置换算关系的 SKU，库存和数量按默认单位管理，下单时数量输入框不显示单位下拉。

### Q: 换算链路可以分叉吗？
A: 不可以。系统采用严格单链路设计，同一 SKU 只能有一条换算链路（如箱→件→包），不可分叉为两条路径。

### Q: 修改换算关系后，已有库存数据会变吗？
A: 不会。库存数据以最小单位（base_unit）的绝对数量存储，修改换算系数只影响展示格式，不改变实际库存数量。
