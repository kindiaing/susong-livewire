# 差异损耗留痕与账务持平设计调研

> 版本：V1.0（探讨稿，未实施）
> 范围：采购 → 入库 → 拣货 → 配送 → 收货（含拒收）→ 退货 → 损耗 全链路的差异/损耗管理
> 原则：**先货后钱** —— 本期设计以"货"的对平为目标，"钱"的联动预留接口、二期接入
> 关联文档：02_FSD 2.9 差异处理 / 2.14 损耗管理、03_DB 6.11/6.14、research/10 配送线路设计

---

## 1 现状诊断（为什么需要这套设计）

| 维度 | 现状 | 问题 |
| :--- | :--- | :--- |
| 库存链 | 采购入库 +、拣货完成 −、退货出库 −、损耗执行 − | 主干通，但**无回补路径**：拒收/配送失败的货扣了库存回不来 |
| 差异链 | 仅「入库差异 → 自动损耗单」一条路径贯通 | 拣货/配送/签收三环节无差异登记入口，`discrepancies` 表空转 |
| 损耗链 | 损耗单全流程可用（审批阈值、扣库存） | 责任方=供应商时不扣应付；损耗与差异的关系未定义 |
| 资金链 | 应收/应付单据在 | 差异、拒收、退货、损耗均不联动金额 |
| 留痕 | audit_logs（人）+ inventory_logs（量）可用 | 缺"业务凭证"层：差异的图、原因、责任方没有统一载体 |

**核心病灶**：把"发现差异"和"处理损耗"混为一谈，导致差异无处登记、损耗无源可溯、库存有去无回、账务无据可对。

## 2 核心设计原理（五条）

### 原理 1：差异与损耗分离 ——「发现 ≠ 处理」

| 概念 | 本质 | 行为 | 载体 |
| :--- | :--- | :--- | :--- |
| **差异（Discrepancy）** | 观察记录：应发 vs 实发、应收 vs 实收 | **不动库存、不动钱**，只登记事实+凭证 | 差异单（发现方创建） |
| **损耗（LossOrder）** | 处理结果：确认这批货灭失/灭失价值 | **动库存、动成本** | 损耗单（处理方创建） |

- 差异单是**事实层**，回答"哪里对不上、差多少、谁发现的、证据是什么"。
- 损耗单是**处置层**，回答"这笔灭失谁承担、库存何时扣、成本进哪本账"。
- 一个差异的处理决策可以是「报损」→ 此时才生成损耗单；也可以是补货/退款/不计 → 不产生损耗。
- **好处**：差异可以挂着慢慢处理（不阻塞发货），损耗永远有源单可溯（杜绝凭空报损）。

### 原理 2：单证链 —— 每个物理交接点必须留下「应 vs 实」

货每换一次手，就有一张证。系统在每个交接点记录三个数量：**应发数、实发数、签收数**。

| 交接点 | 应（账面） | 实（操作录入） | 差异判定 | 发现方 |
| :--- | :--- | :--- | :--- | :--- |
| 供应商 → 平台仓（入库） | 采购数量 | 实收入库数量 | 入库差异 | 仓管 |
| 平台仓 → 拣货（拣货） | 订单需求数量 | 实拣数量 | 拣货差异 | 拣货员 |
| 拣货 → 配送（装车/分货） | 实拣数量 | 实装/实分数量 | 分货差异 | 司机/仓管 |
| 配送 → 商家（签收） | 送达数量 | 商家实收数量 | 实收差异（含拒收） | 商家/司机 |
| 商家 → 平台（售后退货） | 应退数量 | 实退入库数量 | 退货差异 | 仓管 |
| 平台 → 供应商（采购退货） | 应退数量 | 实退数量 | 退货出库记录 | 仓管 |

**规则**：差异只允许在"当前环节"由"当前经手人"登记（前序环节已封账），这就是 FSD 的"差异触发优先级"的落地。

### 原理 3：留痕三件套 —— 人、量、证 三本日志

| 日志 | 回答 | 现有载体 | 要求 |
| :--- | :--- | :--- | :--- |
| 人的轨迹 | 谁在什么时间改了什么状态 | `audit_logs` ✅ | 所有状态变更、金额变更必写 |
| 量的轨迹 | 哪个仓哪个 SKU 何时增减多少、来源单据 | `inventory_logs` ✅ | 一切库存变动必须有 source_type + source_id |
| 证的轨迹 | 差异事实：照片/原因/责任方/处理过程 | `discrepancies` ⚠️ 空转 | 差异单为唯一凭证载体，凭证图片必传 |

三件套串起来 = 任何一件货都可以回答：**从哪来（入库批次）→ 经谁手（audit）→ 在哪灭失（差异单证）→ 谁买单（责任方）**。

### 原理 4：状态机只前进，更正走「红冲」不走「回改」

- 单据状态只许向前流转；已封账（锁定/完成）的单据**物理上不可改**。
- 改错的唯一路径：**授权更正单**（`correction_authorizations`，已有）或**超管回退**（特殊通道，已收敛为仅订单/采购单）。
- 差异处理不改原始单据，只产生**新单据**（补货单/损耗单/退款记录）挂在原单上。
- 这保证了：任何时点的历史快照都是可复算、可审计的。

### 原理 5：四本账对平 —— 账务持平的判定标准

| 账本 | 平衡公式 | 对账口径 |
| :--- | :--- | :--- |
| **库存账** | 期初 + 采购入库 − 拣货出库 − 损耗 − 退货出库 + 拒收回库 + 售后退库 ± 调整 = 期末 | inventory 表 vs inventory_logs 流水重算 |
| **供应商应付账**（二期） | 应付 = 入库金额 − 采购退货金额 − 供应商责任损耗/差异扣款 | 结算单 vs 入库/退货/损耗源单 |
| **商家应收账**（二期） | 应收 = 签收金额 − 拒收金额 − 售后退款 − 差异退款 | 应收单 vs 签收/差异/退货源单 |
| **损耗成本账** | 损耗总额 = Σ(损耗数量 × 成本价)，按责任方拆分平台/供应商 | 损耗单汇总 vs 库存报损流水 |

**持平的定义**：每一本账都能从源单据重算，且与台账一致；任何不平必须能定位到具体单据。

## 3 全流程差异挂点设计

### 3.1 环节 × 差异 × 责任方 × 处理决策 矩阵

| 环节 | 差异类型 | 可选责任方 | 处理决策 | 决策产物（新单据） |
| :--- | :--- | :--- | :--- | :--- |
| 入库 | 少收/残次/其他 | 供应商/平台 | 补货 / 扣款(二期) / 报损 / 不计 | 补货待采项 / 损耗单 |
| 拣货 | 少拣/残次/其他 | 供应商(来料即缺)/平台 | 补货(紧急采购) / 报损 / 不计 | 待采项 / 损耗单 |
| 分货装车 | 少装/错装 | 平台/司机 | 补装 / 报损 / 不计 | 装车更正 / 损耗单 |
| 配送途中 | 灭失/污损 | 司机/平台 | 报损 / 扣款(二期) / 不计 | 损耗单 |
| 签收（实收） | 少收/拒收/残次 | 司机/平台/商家/供应商 | 补送 / 退款(二期) / 报损 / 不计 | 补送任务 / 售后退货单 / 损耗单 |
| 售后退货 | 少退/残次 | 商家/平台 | 退款(二期) / 报损 / 不计 | 退款记录 / 损耗单 |
| 采购退货 | 少退 | 供应商 | 扣款(二期) / 不计 | 结算扣减记录 |

### 3.2 拒收专项流程（签收环节的最复杂分支）

```
商家拒收（全部或部分）
   │
   ├─ 司机在签收单标记拒收数量 + 原因 + 拍照 → 创建实收差异单（类型=拒收）
   │
   ├─ 货随司机带回 → 回仓交接：
   │     ├─ 可再售 ──→ 拒收回库（库存 +，inventory_logs 类型=拒收回库，源单=差异单）
   │     ├─ 不可再售 ─→ 处理决策=报损 → 生成损耗单（责任方：司机/平台/供应商）
   │     └─ 来料问题 ─→ 处理决策=退供应商 → 挂入采购退货单
   │
   └─ 账务（二期）：应收按实收金额结算，拒收部分不计应收
```

**关键设计点**：拒收的货必须「回得了库」——这是当前系统库存回补断点的补法。回库动作由仓管确认（司机带回 ≠ 已入库），防止"货在车上账已回"。

## 4 审核与权限控制设计

### 4.1 三权分立

| 权力 | 角色 | 能做什么 |
| :--- | :--- | :--- |
| **登记权** | 拣货员/司机/仓管/商家(小程序) | 在本环节创建差异单、传凭证、写原因；不能定责任、不能定决策 |
| **处理权** | 运营专员/运营经理 | 定责任方、定处理决策、生成后续单据（补货/报损/补送） |
| **审批权（金额）** | 财务经理 | 涉及金额调整（退款/扣款/超阈值报损）时审批，审批通过才生效 |

### 4.2 阈值分层（复用现有模式）

| 情形 | 流转 |
| :--- | :--- |
| 无金额影响（补货/不计/待定的登记） | 处理权直接办结 |
| 损耗金额 ≤ `loss_approval_threshold`（默认 200 元，系统配置可调） | 处理权直接执行 |
| 损耗金额 > 阈值，或涉及退款/扣款 | 自动挂入**审核中心**（`approvals`，已有 19 节点体系），财务经理审批 |
| 订单已锁定（STATUS_LOCKED）需改金额 | 必须先走**授权更正**（`correction_authorizations`，已有），更正后再处理 |

### 4.3 权限点设计（三级格式 module.page.action）

| 权限点 | 说明 | 默认角色 |
| :--- | :--- | :--- |
| `delivery.discrepancy.create` | 登记差异 | 拣货员/司机/仓管/运营 |
| `delivery.discrepancy.process` | 定责任/定决策 | 运营专员/运营经理 |
| `delivery.discrepancy.approve` | 金额审批 | 财务经理 |
| `delivery.discrepancy.dispute` | 发起/处理争议 | 运营经理 |
| `loss.loss-order.approve` | 损耗审批（已有） | 运营经理 |
| `finance.correction.authorize` | 授权更正（已有） | 财务经理 |

UI 可见性沿用 `@can` + `config/menu.php` 现有机制。

## 5 留痕落地规格

### 5.1 差异单字段利用（现有 `discrepancies` 表已具备）

环节 stage（拣货/配送/实收）、类型 type（少收/拒收/残次/其他）、责任方 party（供应商/平台/司机/商家）、决策 decision（补货/退款/扣款/报损/不计）、状态（待处理→处理中→已处理→已关闭/争议中）、审批 approval_status、凭证图片、关联订单/明细/SKU —— **模型骨架已完整，缺的是创建入口和处理动作**。

### 5.2 唯一性约束（沿用 FSD 规则）

同一订单 + 同一商品 + 同一环节，只允许存在一个未关闭差异单；不同环节按时间顺序各自产生。

### 5.3 库存日志类型补全

| 变动类型 | 方向 | 来源单据 |
| :--- | :--- | :--- |
| 采购入库 | + | purchase_order ✅ |
| 拣货出库 | − | picking_task ✅ |
| 退货出库 | − | purchase_return ✅ |
| 报损 | − | loss_order ✅ |
| **拒收回库** | + | discrepancy（新增类型） |
| **售后退库** | + | order_return（新增类型） |
| 手动调整 | ± | inventory_adjust ✅ |

## 6 账务持平的落地节奏（先货后钱）

### Phase 1：货的对平（本期目标）

1. 三环节差异登记入口（拣货完成页/送货单明细/签收单）
2. 差异处理动作：定责任 + 定决策 + 生成损耗单/补送/补采
3. 库存回补：拒收回库、售后退库两条新增流水类型
4. 损耗单与差异单双向关联（损耗单可溯源到差异单）
5. **对账报表**：库存平衡表（公式重算 vs 台账），每日可跑

**验收标准**：任意 SKU 任意仓库，inventory_logs 流水重算结果 = inventory 台账余额。

### Phase 2：钱的对平（预留接口，本期不做）

1. 差异决策=退款/扣款 → 挂应收/应付调整记录（只登记，不自动改单）
2. 供应商责任损耗 → 结算单扣减项
3. 拒收/退款 → 应收核减
4. 四本账对平报表 + 差异趋势报表

## 7 现有资产 vs 缺口清单

| 资产 | 状态 | 复用方式 |
| :--- | :--- | :--- |
| `discrepancies` 表 + 模型常量 | ⚠️ 骨架完整、无创建入口 | 直接启用，无需改表 |
| 审核中心 `approvals`（19 节点） | ✅ | 差异金额审批挂新节点 |
| 授权更正 `correction_authorizations` | ✅ | 锁定订单金额调整前置 |
| `inventory_logs` + InventoryService | ✅ | 新增 2 个变动类型即可 |
| `loss_orders` 全流程 | ✅ | 补「来源差异单」关联字段 |
| `audit_logs` | ✅ | 差异处理动作补写审计 |
| 权限三级体系 + 菜单 @can | ✅ | 按 4.3 新增权限点 |

| 缺口 | 说明 |
| :--- | :--- |

## 8 一句话总结

> **差异是事实、损耗是结论、日志是证据、审核是闸门、对平是目标。** 先把每一件货的来龙去脉做成可重算的流水，钱的联动自然有据可依。
