# 权限控制 UI 可见性 — 4 种设计方案

> 目标：用户未配置权限时，对应菜单/页面/按钮不可见（而非点击后提示无权限）

---

## 方式一：命名约定法（零额外表）

### 核心思路

权限名直接对应路由名/菜单 key，无需额外映射表。通过 Laravel 原生 `@can` 指令和 `can:` 中间件实现 UI 隐藏 + 路由保护。

### 权限命名约定

```
模块.页面.动作

示例：
org.supplier.view     → 页面可见权限
org.supplier.create   → 新增按钮可见权限
org.supplier.edit     → 编辑按钮可见权限
org.supplier.delete   → 删除按钮可见权限
```

### 菜单配置文件

### 优缺点

| 优点 | 缺点 |
|:---|:---|
| 零额外表，最简单 | 权限名必须严格对齐路由名/菜单 key |
| Laravel 原生 `@can` + `can:` 直接可用 | 改路由名要同步改权限名 |
| 性能最优，无额外查询 | 菜单结构硬编码在配置文件，需发版才能改 |

## 方式二：权限表扩展字段法

### 核心思路

在现有 `permissions` 表上增加路由名、菜单归属、图标、排序等字段，将权限和 UI 信息合并到一张表。

### 数据库变更

```php
// database/migrations/2026_08_01_000001_add_ui_fields_to_permissions_table.php
Schema::table('permissions', function (Blueprint $table) {
    $table->string('route_name')->nullable()->after('name')->comment('对应路由名');
    $table->string('menu_key')->nullable()->after('route_name')->comment('所属菜单标识');
    $table->string('menu_label')->nullable()->after('menu_key')->comment('菜单显示名');
    $table->string('icon')->nullable()->after('menu_label')->comment('菜单图标');
    $table->unsignedInteger('sort_order')->default(0)->after('icon')->comment('排序');
    $table->unsignedBigInteger('parent_id')->nullable()->after('sort_order')->comment('父级权限ID');
});
```

### 数据示例

```
| id | name               | type | route_name            | menu_key      | menu_label | icon    | sort_order | parent_id |
|----|--------------------|------|-----------------------|---------------|------------|---------|------------|-----------|
| 1  | org                | 1    | NULL                  | org           | 组织管理   | building| 1          | NULL      |
| 2  | org.supplier       | 2    | org.supplier.index    | org.supplier  | 供应商     | NULL    | 1          | 1         |
| 3  | org.supplier.view  | 3    | org.supplier.index    | NULL          | NULL       | NULL    | 0          | 2         |
| 4  | org.supplier.create| 3    | org.supplier.store    | NULL          | NULL       | NULL    | 0          | 2         |
| 5  | org.supplier.edit  | 3    | org.supplier.update   | NULL          | NULL       | NULL    | 0          | 2         |
| 6  | org.supplier.delete| 3    | org.supplier.destroy  | NULL          | NULL       | NULL    | 0          | 2         |
```

### 菜单查询逻辑

```php
// app/Services/MenuService.php
class MenuService
{
    public function getVisibleMenu(): Collection
    {
        $user = auth()->user();
        $permissionIds = $user->getAllPermissions()->pluck('id');

        return Permission::query()
            ->whereIn('id', $permissionIds)
            ->whereNotNull('menu_key')          // 只取有菜单标识的权限
            ->where('type', 2)                  // 页面级权限
            ->orderBy('sort_order')
            ->get()
            ->groupBy('parent_id');             // 按模块分组
    }

    public function getMenuTree(): Collection
    {
        $user = auth()->user();
        $permissionIds = $user->getAllPermissions()->pluck('id');

        // 模块级
        $modules = Permission::where('type', 1)->orderBy('sort_order')->get();

        return $modules->map(function ($module) use ($permissionIds) {
            $pages = Permission::query()
                ->where('parent_id', $module->id)
                ->where('type', 2)
                ->whereIn('id', $permissionIds)
                ->whereNotNull('menu_key')
                ->orderBy('sort_order')
                ->get();

            if ($pages->isEmpty()) {
                return null;
            }

            return [
                'key'      => $module->menu_key,
                'label'    => $module->menu_label,
                'icon'     => $module->icon,
                'children' => $pages->map(fn($p) => [
                    'key'   => $p->menu_key,
                    'label' => $p->menu_label,
                    'route' => $p->route_name,
                ])->values(),
            ];
        })->filter()->values();
    }
}
```

### 路由保护

```php

```

### 优缺点

| 优点 | 缺点 |
|:---|:---|
| 一张表搞定，查询简单 | permissions 表职责变重 |
| 运行时可动态修改菜单（改数据库即可） | button 级权限的 menu_key/route_name 为空，有冗余字段 |
| 菜单排序/图标可配置 | 需 Migration + 改 Model fillable |
| 权限和 UI 信息强关联，不会错位 | 多角色同权限时菜单信息重复存储 |

## 方式三：独立映射表法

### 核心思路

新建 `permission_ui` 表，将权限与 UI 元素（菜单/页面/按钮）解耦，一个权限可映射多个 UI 元素。

### 数据库变更

```php
// database/migrations/2026_08_01_000001_create_permission_ui_table.php
Schema::create('permission_ui', function (Blueprint $table) {
    $table->id();
    $table->foreignId('permission_id')->constrained()->cascadeOnDelete()->comment('关联权限ID');
    $table->enum('element_type', ['menu', 'page', 'button'])->comment('UI元素类型');
    $table->string('element_key')->comment('元素标识（如 org.supplier）');
    $table->string('element_label')->comment('显示名称');
    $table->string('route_name')->nullable()->comment('对应路由名');
    $table->string('parent_key')->nullable()->comment('父级元素key');
    $table->string('icon')->nullable()->comment('图标');
    $table->unsignedInteger('sort_order')->default(0)->comment('排序');
    $table->timestamps();

    $table->unique(['permission_id', 'element_type', 'element_key']);
});
```

### 数据示例

```
| id | permission_id | element_type | element_key         | element_label | route_name           | parent_key | icon    | sort_order |
|----|---------------|-------------|---------------------|---------------|----------------------|------------|---------|------------|
| 1  | 1(org)        | menu        | org                 | 组织管理      | NULL                 | NULL       | building| 1          |
| 2  | 2(org.supplier)| page       | org.supplier        | 供应商        | org.supplier.index   | org        | NULL    | 1          |
| 3  | 3(.view)      | button      | org.supplier.create | 新增          | NULL                 | org.supplier| NULL   | 1          |
| 4  | 4(.create)    | button      | org.supplier.edit   | 编辑          | NULL                 | org.supplier| NULL   | 2          |
| 5  | 5(.edit)      | button      | org.supplier.delete | 删除          | NULL                 | org.supplier| NULL   | 3          |
| 6  | 6(.delete)    | button      | org.merchant.create | 新增          | NULL                 | org.merchant| NULL   | 1          |
```

### Model

```php
// app/Models/PermissionUi.php
class PermissionUi extends Model
{
    protected $table = 'permission_ui';

    protected $fillable = [
        'permission_id', 'element_type', 'element_key',
        'element_label', 'route_name', 'parent_key',
        'icon', 'sort_order',
    ];

    public function permission(): BelongsTo
    {
        return $this->belongsTo(Permission::class);
    }
}
```

### 菜单服务

```php
// app/Services/MenuService.php
class MenuService
{
    public function getVisibleMenu(): Collection
    {
        $user = auth()->user();
        $permissionIds = $user->getAllPermissions()->pluck('id');

        $uiElements = PermissionUi::query()
            ->whereIn('permission_id', $permissionIds)
            ->orderBy('sort_order')
            ->get();

        // 构建模块级菜单
        $modules = $uiElements->where('element_type', 'menu');
        $pages   = $uiElements->where('element_type', 'page');

        return $modules->map(function ($module) use ($pages) {
            $children = $pages->where('parent_key', $module->element_key);

            if ($children->isEmpty()) {
                return null;
            }

            return [
                'key'      => $module->element_key,
                'label'    => $module->element_label,
                'icon'     => $module->icon,
                'children' => $children->map(fn($p) => [
                    'key'   => $p->element_key,
                    'label' => $p->element_label,
                    'route' => $p->route_name,
                ])->values(),
            ];
        })->filter()->values();
    }

    public function getVisibleButtons(string $pageKey): Collection
    {
        $user = auth()->user();
        $permissionIds = $user->getAllPermissions()->pluck('id');

        return PermissionUi::query()
            ->whereIn('permission_id', $permissionIds)
            ->where('element_type', 'button')
            ->where('parent_key', $pageKey)
            ->orderBy('sort_order')
            ->pluck('element_key');
    }
}
```

### 优缺点

| 优点 | 缺点 |
|:---|:---|
| 解耦最彻底，权限和 UI 独立维护 | 多一张表 + 一层关联查询 |
| 一个权限可映射多个 UI 元素（如一个权限控制2个按钮） | Seeder 维护成本增加 |
| UI 元素可独立增删，不影响权限逻辑 | 查询时需要 join 或两次查询 |
| 运行时完全可动态配置 | 复杂度最高 |

## 四种方式对比总结

| 维度 | 方式一·命名约定 | 方式二·扩展字段 | 方式三·独立映射表 | 方式四·配置文件 |
|:---|:---|:---|:---|:---|
| **额外数据表** | 无 | 无（改现有表） | 1 张新表 | 无 |
| **菜单来源** | 配置文件 | 数据库查询 | 数据库查询 | 配置文件 |
| **按钮来源** | Blade 硬编码 `@can` | Blade 硬编码 `@can` | 数据库查询 | 配置文件 |
| **运行时可配置** | 否 | 是 | 是 | 否 |
| **数据库查询次数** | 0（权限已缓存） | 1 次 | 1~2 次 | 0 |
| **权限-UI 耦合度** | 高（命名强绑定） | 中（同表不同字段） | 低（独立表解耦） | 高（配置文件绑定） |
