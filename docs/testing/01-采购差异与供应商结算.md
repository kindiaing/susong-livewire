# 01 采购差异与供应商结算流程测试清单

> 覆盖链路：创建采购单 → 提交 → 发货 → 入库（故意少收产生差异）→ 差异处理 → 采购单完成 → 新增供应商结算（差异货款自动少算）→ 出纳登记付款 → 财务经理审核 → 出纳执行付款 → 结清/办结

## 前置条件

| 项目 | 要求 |
|---|---|
| 账号权限 | 出纳/财务经理两个角色账号（或一个超管 admin 覆盖全部操作） |
| 审核开关 | 系统管理 → 审核管理 → 「供应商付款录入 supplier_payment」需为**开启**状态（默认开启） |
| 系统配置 | 采购设置允许差异入库（`purchase_allow_discrepancy=true`，若关闭实收≠订购会直接报错拦截） |
| 基础数据 | 至少一个启用状态的供应商、一个启用商品（含 SKU）、一个仓库 |

## 测试数据建议

- 采购单 A：订购 10 件，实收 8 件（差异 2 件，验证少收场景）
- 建议商品单价取整（如 ¥10/件），便于心算核对金额

---

## 第一步：创建并提交采购单

- [ ] 1.1 登录后点击顶部导航「**采购管理**」→ 左侧菜单「**采购单管理**」
- [ ] 1.2 点击右上角「**新增采购**」按钮
- [ ] 1.3 选择供应商、仓库，添加商品明细（如：商品 ×10，单价 ¥10）
- [ ] 1.4 点击「**提交**」，预期：采购单生成，状态为「待审核/已提交」
- [ ] 1.5 在详情页点击「**审核**」（或由有审核权限的账号操作），预期：状态变为「已审核」

## 第二步：发货与入库（制造差异）

- [ ] 2.1 进入采购单详情页，点击「**发货**」按钮，预期：状态变为「已发货」
- [ ] 2.2 点击顶部「**入库**」按钮，弹出「采购入库」弹窗
- [ ] 2.3 选择入库仓库、批次号（选填）
- [ ] 2.4 明细行「实际数量」填 **8**（订购 10），观察差异列**橙色高亮**并显示差异 2
- [ ] 2.5 「差异原因」可留空或填写（如「供应商短装」）
- [ ] 2.6 实际单价可微调（如 ¥10 不变）
- [ ] 2.7 点击「**确认入库**」，预期：
  - 采购单状态变为「已入库」
  - 入库金额按实际数量计价（8 × ¥10 = ¥80，而非订购的 ¥100）
  - 库存增加 8 件（到 库存管理 可核对）

## 第三步：差异处理台处理差异

- [ ] 3.1 点击顶部导航「**配送管理**」→「**差异处理**」（路由 /discrepancies）
- [ ] 3.2 预期：列表自动出现该采购单的差异记录（环节=入库，类型=少收，差异 2 件）——**入库时自动登记，无需手动创建**
- [ ] 3.3 打开差异单，选择处理决策（补货 / 报损 / 退款 / 扣款 / 不计）
- [ ] 3.4 若选「报损」：预期可选自动生成损耗单（到 库存拣货 → 损耗管理 核对）
- [ ] 3.5 处理完成，预期：差异单状态变为已处理

## 第四步：完成采购单

- [ ] 4.1 回到采购单详情页
- [ ] 4.2 若存在**未处理差异**，点「完成」预期被拦截（提示需先处理差异）
- [ ] 4.3 差异已处理后再点「**完成**」，预期：状态变为「已完成」

## 第五步：新增供应商结算

- [ ] 5.1 点击顶部导航「**财务管理**」→「**供应商结算**」
- [ ] 5.2 点击右上角「**新增结算**」按钮
- [ ] 5.3 选择供应商、结算周期起止日期（覆盖入库时间）、服务费可留空
- [ ] 5.4 点击保存，预期生成结算单：
  - 汇总金额 = 该周期内已入库/已完成且未结算过的采购单**实际入库金额**之和（¥80，差异的 2 件自动少算）
  - 若周期内有已完成退货单，退货扣减自动汇总
  - 应付金额 = 汇总金额 − 退货扣减 − 服务费
- [ ] 5.5 列表页核对应付/已付/待付金额列显示正确
- [ ] 5.6 用相同供应商、相同周期再次「新增结算」，预期：**不重复结算**已结算过的采购单

## 第六步：出纳登记付款

- [ ] 6.1 用出纳账号（或有 finance.supplier-settlement.pay 权限的账号）进入结算单详情页
- [ ] 6.2 顶部「**登记付款**」按钮可见（状态为待结算/部分付款时）
- [ ] 6.3 点击登记付款，填写金额（如 ¥30，部分付款）
- [ ] 6.4 提交后预期：
  - 付款记录状态「**待审核**」
  - **已付金额仍为 ¥0**（审核通过前不累计）
  - 系统管理 → 审核列表出现一条待审核的供应商付款记录

## 第七步：财务经理审核

- [ ] 7.1 用财务经理账号登录
- [ ] 7.2 系统管理 →「**审核列表**」（/approvals），待审核 Tab 显示该付款
- [ ] 7.3 点击「**通过**」，预期：
  - 审批记录状态已通过
  - 付款记录状态变为「已通过待执行」
  - **已付金额仍不累计**（此时只是审核通过）
  - 出纳收到「供应商付款待执行」通知（通知铃铛）
- [ ] 7.4 另登记一笔付款，点「**拒绝**」，预期：必须填写拒绝原因，付款记录状态「已拒绝」，不进入执行

## 第八步：出纳执行付款

- [ ] 8.1 切回出纳账号，进入结算单详情页 →「**付款记录**」Tab
- [ ] 8.2 已审核通过的付款行显示蓝色「**执行付款**」小按钮
- [ ] 8.3 点击执行付款，弹窗中付款方式/交易号/备注**均可不填**
- [ ] 8.4 点击「确认执行」，预期：
  - 已付金额累计（¥30）
  - 结算状态变为「部分付款」
  - 付款记录状态「已执行」，如填了交易号则显示
- [ ] 8.5 再执行剩余金额（¥50），预期：结算状态「已结清」、待付 ¥0、「登记付款」按钮消失
- [ ] 8.6 通知：结清后申请人收到「结算完成」通知

## 第九步：办结

- [ ] 9.1 已结清状态下点击「**办结**」按钮
- [ ] 9.2 预期：状态变为「已办结」，记录办结人/办结时间
- [ ] 9.3 办结后预期：登记付款/办结按钮均消失，不可再付款

## 关键校验点汇总

| # | 校验点 | 预期 |
|---|---|---|
| 1 | 入库差异计价 | 结算按实际入库金额，少收部分不进汇总 |
| 2 | 审核与执行分离 | 审核通过≠付款完成，已付金额仅在执行后累计 |
| 3 | 待执行徽章 | 列表页状态列显示蓝色「待执行」徽章 |
| 4 | 通知金额 | 通知内容金额只有单个 ¥ 符号（已修复双¥问题） |
| 5 | 超付拦截 | 登记付款金额超过待付金额时被拦截报错 |
| 6 | 重复结算拦截 | 同一采购单不会被两张结算单重复结算 |
