## 🔀 Git 管理

- 📌 **分支策略**：功能开发在独立分支进行，用户确认后方可合并到 main
- 🧪 **合并前提**：用户测试功能通过后，再合并到主分支
- 🌿 **新功能提醒**：开发新模块时，主动提醒用户创建功能分支
- 🧹 **提交前清理**：每次 `git commit` 前，必须删除 docs 目录所有文件中的 AIGC 痕迹（包括 YAML front matter 中的 `AIGC:` 块及其 `---` 分隔符）；同时检查 UTF-8 无 BOM 编码

## ✅ 验收标准

合并到主分支前，必须同时满足以下条件：

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 🗃️ Migration 整洁 | 确保只有 `create` 建表语句，无 `alter` 新增/修改字段；有的话合并到对应 `create` 迁移中 |
| 2 | ⚙️ `admin:install` | 仅安装核心数据，执行成功 |
| 3 | 🌱 `admin:install --seed` | 安装核心数据 + 测试数据，执行成功 |
| 4 | 📋 列配置 | 不同菜单有独立 `getDefaultColumns()`，只显示关键信息，隐藏过多/过长字段 |
| 5 | ✂️ 长文本截断 | 列表页长文本用 truncate + hover(popover/title) 显示，详情弹窗显示全部内容 |
| 6 | 🪟 弹窗遮罩 | 遮罩不可点击关闭，必须点关闭/取消按钮才能关闭 |

> 💡 以上两条命令分别通过，才能保证项目可干净交付和初始化安装。

## ⚙️ 业务规则共识（逐步沉淀）

- 🔒 **单据状态锁定**：单据仅初始状态可编辑/删除；提交后须管理员/超管「回退」状态才可改；回退仅改状态 + AuditLog，不做关联单据联动；模型层统一 `canEdit()` / `canRollbackStatus()` / `rollbackTargets()`
- 🎛️ **开关 vs 权限**：审核/流程类开关走 `system_configs`（系统设置页面配置），按钮级可见/可用走权限点（`@can` + 服务端校验）
- 📦 **差异与损耗分离**：差异单只登记事实（不动库存和钱），损耗单才是处置（审核执行后动库存成本）；退款/扣款的金额联动为二期
