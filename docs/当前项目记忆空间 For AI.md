# 项目记忆空间

> 本文档为 AI 协作记忆区，记录项目核心规则、验收标准和开发规范，确保每次会话上下文一致。

---

## 🔀 Git 管理

- 📌 **分支策略**：功能开发在独立分支进行，用户确认后方可合并到 main
- 🧪 **合并前提**：用户测试功能通过后，再合并到主分支
- 🌿 **新功能提醒**：开发新模块时，主动提醒用户创建功能分支
- 🧹 **提交前清理**：推送到远程仓库前，必须删除 docs 目录文件前后的 AIGC 痕迹

---

## ✅ 验收标准

合并到主分支前，必须同时满足以下条件：

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 🗃️ Migration 整洁 | 确保只有 `create` 建表语句，无 `alter` 新增/修改字段；有的话合并到对应 `create` 迁移中 |
| 2 | ⚙️ `admin:install` | 仅安装核心数据，执行成功 |
| 3 | 🌱 `admin:install --seed` | 安装核心数据 + 测试数据，执行成功 |

> 💡 以上两条命令分别通过，才能保证项目可干净交付和初始化安装。

---

## 📖 开发文档规范

- 📚 **先读后写**：开发前先阅读 `docs/` 目录下的开发文档，理解现有架构再动手
- 📋 **列清单确认**：修改代码前，先列出当前任务清单，供用户选择或确认后再执行
- 🔄 **文档与代码同步**：每次迭代后，同步更新开发文档，保持文档与代码一致
