## 1 Blade 视图文件编码规范

### 1.1 禁止 UTF-8 BOM

**问题根因**：Blade 视图文件开头包含 UTF-8 BOM（`\xEF\xBB\xBF`）会在组件根 `<div>` 前产生不可见文本节点，导致 Livewire 4 morphing 算法将 `wire:id` 绑定到错误子元素，使弹窗内容和操作按钮脱离组件 DOM 边界。

**规范**：
- 所有 `.blade.php` 文件必须使用 **UTF-8 无 BOM** 编码
- 新建文件时确认编辑器/IDE 的默认编码为 `UTF-8 (without BOM)`
- 每次迭代完成后，运行以下命令检查并清除 BOM：

```powershell
# 检查含 BOM 的 Blade 文件
Get-ChildItem -Path "resources\views" -Recurse -Filter "*.blade.php" | ForEach-Object {
    $bytes = [System.IO.File]::ReadAllBytes($_.FullName)
    if ($bytes.Length -ge 3 -and $bytes[0] -eq 0xEF -and $bytes[1] -eq 0xBB -and $bytes[2] -eq 0xBF) {
        Write-Host "BOM found: $($_.FullName)"
    }
}
```

## 2 Toast 消息通知规范

### 2.1 统一使用 WithToast Trait

**问题根因**：Livewire 的 `dispatch('toast', message: '...')` 发出的事件 detail 中字段名为 `message`，但前端 Alpine `$toast.show()` 期望 `title` 字段，导致 Toast 无文字显示。

**规范**：
- 所有 Livewire 组件必须 `use WithToast;` Trait
- **禁止**直接使用 `$this->dispatch('toast', message: '...')`
- 使用以下方法发送 Toast：

```php
// ✅ 正确方式
$this->toastSuccess('操作成功');
$this->toastError('操作失败');
$this->toastWarning('请注意', '详细说明');
$this->toastInfo('提示信息');

// ❌ 错误方式 — 禁止使用
$this->dispatch('toast', message: '...', type: 'success');
```

### 2.2 前端事件字段约定

Livewire dispatch 的 Toast 事件统一使用以下字段：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| `title` | string | 是 | 主标题（必填） |
| `description` | string | 否 | 补充说明 |
| `type` | string | 是 | `success` / `error` / `warning` / `info` / `default` |

### 2.3 WithToast Trait 文件位置

`app/Livewire/Traits/WithToast.php`

## 3 Button 元素 type 属性规范

### 3.1 必须添加 type="button"

**问题根因**：在弹窗内，`<button>` 未指定 `type` 时默认为 `submit`，会触发表单提交和 Livewire 验证管道，导致 `wire:click="closeModal"` 被拦截。

**规范**：
- 所有 `<button>` 元素**必须显式声明 `type="button"`**（除真正需要 submit 行为的保存按钮外）
- 弹窗中的取消按钮、工具栏按钮、图标操作按钮等一律添加 `type="button"`

```html
<!-- ✅ 正确 -->
<button type="button" wire:click="closeModal">取消</button>
<button type="button" wire:click="openEditModal({{ $id }})">
    <svg>...</svg>
</button>

<!-- ❌ 错误 — 缺少 type="button" -->
<button wire:click="closeModal">取消</button>
```

## 4 Checkbox 与 wire:click 冲突规范

### 4.1 不要同时绑定 wire:model.live 和 wire:click

**问题根因**：当 checkbox 同时绑定 `wire:model.live="formArray"` 和 `wire:click="toggleMethod()"` 时，Livewire 先执行 model 绑定（自动切换值），再执行 click 方法，导致自定义逻辑基于已被修改的数组做判断，产生始终全选等异常行为。

**规范**：
- 自定义联动逻辑的 checkbox：只用 `wire:click`，用 `@checked()` 手动控制选中状态
- 简单单选/多选 checkbox：只用 `wire:model.live`，不用 `wire:click`

```html
<!-- ✅ 正确 — 联动 checkbox -->
<input type="checkbox"
       wire:click="toggleModulePermissions({{ $module->id }})"
       @checked(in_array($module->id, $formPermissionIds)) />

<!-- ✅ 正确 — 简单多选 -->
<input type="checkbox"
       value="{{ $item->id }}"
       wire:model.live="selectedIds" />

<!-- ❌ 错误 — 两者同时绑定 -->
<input type="checkbox"
       wire:model.live="formPermissionIds"
       wire:click="toggleModulePermissions({{ $module->id }})" />
```

## 5 金额字段规范

### 5.1 三层分离架构

系统金额体系采用**三层分离**设计，确保计算精度和显示灵活性：

| 层面 | 单位 | 说明 |
|:---|:---|:---|
| 存储层 | 厘（1厘 = ¥0.001） | BIGINT 整数，固定不变，所有金额字段统一使用厘 |
| 计算层 | 厘 | 后端所有运算（加减乘除、汇总、校验）均在厘级完成，零精度丢失 |
| 显示层 | 元（可配置精度） | 通过 `money_format()` 将厘转为元显示，精度和舍入方式可按模块配置 |

**核心铁律**：

- 汇总金额**永远是后端厘级求和**的结果，不是前端把显示值加起来
- 2位显示下，明细各自舍入后求和可能与汇总存在几分钱尾差（数学规律），这是正常现象
- 所有金额字段数据库统一使用 `bigInteger`，存储单位为**厘**
- 禁止在前端对明细金额求和作为汇总

### 5.2 尾差处理策略

采用**策略A：汇总精确，明细各自舍入显示**。

- 后端汇总 = SUM(所有明细的厘值)，再调用 `money_format()` 显示
- 前端不做明细求和，汇总值从后端直接取
- 允许"明细显示之和 ≠ 汇总显示"（视觉尾差），数据层绝对一致
- 列表页底部提示：`* 金额以厘级计算为准，显示可能存在舍入尾差`

### 5.3 助手函数

```php
// 金额格式化：厘 → 显示字符串（支持模块级舍入配置）
money_format(int|float|null $cents, bool $withSymbol = true, ?string $module = null): string

// 金额舍入：厘 → 元（浮点），按精度和模式
money_round(int|float $cents, int $precision = 2, string $mode = 'round'): float

// 金额反格式化：元 → 厘（存储，不受精度配置影响）
money_to_cents(string|float|null $yuan): int

// 称重数量格式化：厘斤 → 斤（支持称重精度配置）
weight_format(int|float|null $liangin, bool $withUnit = false, ?int $precision = null): string

// 称重数量反格式化：斤 → 厘斤（存储）
weight_to_liangin(string|float|null $jin): int
```

**调用示例**：

```php
// ✅ 正确 — 基本用法（向后兼容）
money_format($order->total_amount);                     // → ¥1,234.56
money_format($order->total_amount, false);              // → 1,234.56（不带¥）

// ✅ 正确 — 指定模块舍入（采购模块用截断，充值模块用向上取整）
money_format($item->amount, true, 'purchase');          // → 按采购模块配置舍入
money_format($item->amount, true, 'recharge');           // → 按充值模块配置舍入

// ✅ 正确 — 输入端转厘
'purchase_price' => money_to_cents($this->formPurchasePrice),

// ✅ 正确 — 称重数量
weight_format(2130, true);                               // → 2.130斤
weight_to_liangin('2.13');                               // → 2130

// ❌ 错误 — 不要手动除以1000
number_format($order->total_amount / 1000, 2);          // 不使用 money_format

// ❌ 错误 — 不要拼接"元"后缀（money_format 已含¥符号）
money_format($item->total_amount) . ' 元';              // 会显示 ¥23.00 元
```

### 5.4 舍入模式枚举

| 值 | 含义 | 示例（厘→元，2位精度） | 示例（3位精度） |
|:---|:---|:---|:---|
| `round` | 四舍五入 | ¥3.145 → ¥3.15 | ¥3.1455 → ¥3.146 |
| `round_up` | 向上取整 | ¥3.141 → ¥3.15 | ¥3.1411 → ¥3.142 |
| `round_down` | 向下取整 | ¥3.149 → ¥3.14 | ¥3.1499 → ¥3.149 |
| `truncate` | 截断抹零 | ¥3.149 → ¥3.14 | ¥3.1455 → ¥3.145 |

> 注意：2位精度下 `truncate` 和 `round_down` 结果一致；3位精度下才出现差异。

### 5.5 各模块默认舍入配置

| 模块 | config_key | 默认舍入 | 推荐理由 |
|:---|:---|:---|:---|
| 全局默认 | `money.default_round_mode` | `round` | 四舍五入最常见 |
| 订单 | `money.order_round_mode` | `round` | 消费者标准四舍五入 |
| 采购 | `money.purchase_round_mode` | `truncate` | 采购金额截断抹零，供应商让利 |
| 充值 | `money.recharge_round_mode` | `round_up` | 充值向上取整，保护平台 |
| 结算 | `money.settlement_round_mode` | `round` | 财务标准四舍五入 |
| 取价/促销 | `money.price_round_mode` | `round` | 价格展示四舍五入 |
| 库存损耗 | `money.inventory_round_mode` | `truncate` | 损耗截断抹零，避免虚增 |
| 发票 | `money.invoice_round_mode` | `round` | 税务合规四舍五入 |

### 5.6 称重精度配置

称重数量精度和金额显示精度是**两个独立维度**：

| 配置项 | config_key | 默认值 | 说明 |
|:---|:---|:---|:---|
| 金额显示精度 | `money.display_precision` | 2 | 2=分（¥8.00），3=厘（¥8.000） |
| 称重数量精度 | `money.weighing_precision` | 3 | 2=普通秤（0.05斤），3=精密秤（0.001斤） |

| 场景 | 数量精度 | 金额精度 | 典型业务 |
|:---|:---|:---|:---|
| 精密秤（1克级） | 3位 | 3位 | 高价值水产、肉品 |
| 普通秤（50克级） | 2位 | 2位 | 蔬菜、粮油 |
| 整件计价 | 0位 | 2位 | 标品、桶装油 |

### 5.7 配置入口

所有金额精度和舍入配置通过**系统管理 → 系统配置 → 金额精度**分组管理，修改即时生效（无需重启）。

### 5.8 批量计算规范

批量金额计算**必须在厘级**完成，最终结果才调用 `money_format()` 显示：

```php
// ✅ 正确 — 厘级计算
$totalCents = 0;
foreach ($items as $item) {
    $totalCents += $item->price * $item->quantity / 1000;  // 厘级运算
}
$total = money_format($totalCents);  // 最后一步才显示

// ❌ 错误 — 元级计算
$total = 0;
foreach ($items as $item) {
    $total += money_format($item->price, false) * $item->quantity;  // 浮点精度丢失
}
```

## 6 弹窗取消按钮规范

### 6.1 取消按钮必须调用 closeXxxModal()

**规范**：
- 弹窗取消按钮调用独立的 `closeXxxModal()` 方法（如 `closeCreateModal` / `closeEditModal` / `closePermissionModal`）
- `closeXxxModal()` 方法内部调用 `$this->resetErrorBag()`
- **不要**用 `wire:model` 绑定 `showXxxModal` 来间接关闭，因为弹窗内有 `wire:model` 绑定时，Livewire 验证管道会拦截关闭操作

```php
// ✅ 正确
public function closeModal(): void
{
    $this->showModal = false;
    $this->resetErrorBag();
    $this->resetForm();
}

// ❌ 错误 — 直接设置属性不触发 resetErrorBag
public function closeModal(): void
{
    $this->showModal = false;
}
```

## 7 列表页增强规范

### 7.1 必须实现的 Trait

每个列表页组件必须实现以下 Trait：

| Trait | 用途 |
|:---|:---|
| `WithRowSelection` | 多选、批量操作 |
| `WithColumnVisibility` | 自定义显示列 |
| `WithExcelExport` | Excel 导出 |
| `WithExcelImport` | Excel 导入 |
| `WithToast` | Toast 消息通知 |
| `WithListCrud` | 样板 CRUD 方法（openCreateModal/openEditModal/closeModal/confirmDelete/delete/closeDeleteConfirm/resetForm/resetFilters） |

### 7.2 列表页必备功能

- 行前 checkbox 多选
- 批量修改（基于选中行）
- 高级查询（搜索 + 筛选）
- 自定义显示列
- 批量导入导出到 Excel
- 导出支持自定义列（默认导出全部）

### 7.3 WithListCrud Trait 规范

**问题根因**：28 个 List 组件共享约 120 行样板 CRUD 代码（openCreateModal/openEditModal/closeModal/confirmDelete/delete/closeDeleteConfirm/resetForm/resetFilters），总计约 3,360 行高度重复。

**规范**：
- 所有 CRUD 列表页组件必须 `use WithListCrud;` Trait
- Trait 提供以下默认方法，组件无需重复定义：

```php
// WithListCrud Trait 提供的默认方法：
public function openCreateModal(): void    // 打开创建弹窗
public function openEditModal(int $id): void  // 打开编辑弹窗（需组件实现 findForEdit）
public function closeModal(): void         // 关闭弹窗 + resetErrorBag
public function confirmDelete(int $id): void  // 确认删除弹窗
public function closeDeleteConfirm(): void   // 关闭删除确认
public function resetFilters(): void       // 重置搜索 + 翻页

// 组件仍需自行实现的方法（业务差异化）：
public function save(): void               // 保存逻辑（验证规则各不同）
public function delete(): void             // 删除逻辑（可能含关联清理）
public function resetForm(): void          // 重置表单字段
public function toggleStatus(int $id): void // 切换状态（部分组件无此功能）
```

- 组件如需自定义某个方法，直接覆写即可（Trait 方法优先级低于组件）
- 只读/日志组件不使用 WithListCrud，但仍需实现 WithColumnVisibility + WithExcelExport + WithExcelImport

### 7.4 列配置默认值规范

**问题根因**：部分列表页 `getDefaultColumns()` 返回全部列或仅排除 id，导致表格列过多、信息密度低。用户还需手动隐藏大量不需要的列。

**规范**：
- `getDefaultColumns()` 只返回**该页面最关键的 5-8 个业务列**，而非全部列
- `id` 列默认不显示（技术字段，非业务需要）
- 辅助性/低频列默认隐藏：备注(remark)、地址(address)、创建时间(created_at)等
- 金额类、状态类、名称类列默认显示
- 具体规则：

| 列类型 | 默认显示 | 示例 |
|:---|:---|:---|
| 核心标识 | 是 | 名称(name)、编号(code)、订单号(order_no) |
| 金额 | 是 | 金额(amount)、总额(total) |
| 状态 | 是 | 状态(status)、审核状态(approval_status) |
| 分类/类型 | 是 | 类型(type)、结算周期(settlement_cycle) |
| 时间 | 视情况 | 截止时间默认显示，创建时间默认隐藏 |
| 联系方式 | 是 | 联系人、联系电话 |
| 地址 | 否 | 地址太长，默认隐藏 |
| 备注 | 否 | 备注默认隐藏，hover 或详情弹窗查看 |
| ID | 否 | 技术字段，默认隐藏 |

**示例**：

```php
// ✅ 正确 — 供应商列表默认显示 8 列
public function getDefaultColumns(): array
{
    return ['name', 'contact_name', 'contact_phone', 'settlement_cycle', 'status', 'bank_name', 'bank_account', 'created_at'];
}

// ❌ 错误 — 只排除 ID，其他全部显示
public function getDefaultColumns(): array
{
    return collect($this->getAllColumns())->pluck('key')->reject(fn($k) => $k === 'id')->toArray();
}
```

### 7.5 弹窗规范

**弹窗遮罩关闭行为：**

- 弹窗遮罩（backdrop）**不允许点击关闭**
- 用户必须点击弹窗内的"关闭"或"取消"按钮才能关闭弹窗
- 防止用户误触遮罩导致填写中的表单数据丢失

```html
<!-- ✅ 正确 — 遮罩不可点击关闭 -->
<div class="fixed inset-0 bg-black/50" aria-hidden="true"></div>

<!-- ❌ 错误 — 遮罩可点击关闭 -->
<div class="fixed inset-0 bg-black/50" wire:click="closeModal"></div>
```

**详情弹窗：**

- 点击列表行或"查看"按钮时，弹窗显示该记录的所有字段完整内容
- 详情弹窗是查看所有信息的入口，列表只展示摘要

**长文本截断与 hover 提示：**

```html
<!-- ✅ 正确 — 截断 + hover 显示全文 -->
<td class="px-4 py-2 max-w-[200px] truncate" title="{{ $item->description }}">
    {{ Str::limit($item->description, 30) }}
</td>
```

### 7.6 导入导出规范

- 导入导出必须使用 `GenericImport` / `GenericExport` 类
- 组件需实现 `getImportColumnMap()` / `getAllColumns()` / `getExportQuery()` / `getExportFileName()`

## 8 Blade 组件 + Alpine.js 兼容规范

### 8.1 x-for 循环内不使用 Blade 组件

**问题根因**：Alpine `x-for` 循环内的变量作用域与 Blade 编译期不互通，Blade 组件在编译期无法访问 Alpine 运行时变量。

**规范**：
- 在 `x-for` 循环内，使用内联 HTML/SVG 而非 Blade 组件
- 或将 `x-for` 替换为 Blade `@foreach`
